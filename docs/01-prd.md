# PRD — Phikadfest

> เอกสารกำหนดขอบเขตผลิตภัณฑ์ ฉบับเริ่มต้น (Phase 0)
> อัปเดตล่าสุด: 2026-08-19

## 1. ปัญหาที่จะแก้

ข้อมูลงานเทศกาลและกิจกรรมในประเทศไทย **กระจัดกระจาย** อยู่ตามเพจ Facebook ของผู้จัดแต่ละราย, กลุ่มไลน์, เว็บของหน่วยงานราชการแต่ละจังหวัด และโพสต์ในกลุ่มความสนใจเฉพาะทาง ผลคือ:

- คนในพื้นที่ **ไม่รู้ว่ามีงานอะไรจัดใกล้ตัว** จนกระทั่งงานผ่านไปแล้ว
- นักท่องเที่ยว **วางแผนทริปโดยไม่รู้ว่าช่วงนั้นมีงานอะไร** ในจังหวัดที่จะไป
- ผู้จัดงานรายเล็ก **เข้าถึงคนได้แค่วงในของตัวเอง**

ผลกระทบที่ตามมาคือโอกาสทางเศรษฐกิจในท้องถิ่นหายไป — คนไม่ได้ออกไปเที่ยว ไม่ได้ใช้จ่ายในพื้นที่ ทั้งที่งานมีอยู่จริง

## 2. เป้าหมายของผลิตภัณฑ์

**หนึ่งประโยค:** เว็บไซต์ที่ตอบได้ทันทีว่า "ตอนนี้มีงานอะไรน่าไปบ้าง — ใกล้ฉัน หรือในจังหวัดที่ฉันกำลังจะไป"

เป้าหมายรอง:
- กระตุ้นการเดินทางและการใช้จ่ายในท้องถิ่น
- เป็นช่องทางฟรีให้ผู้จัดงานรายเล็กเข้าถึงคนได้กว้างขึ้น

## 3. กลุ่มผู้ใช้

| กลุ่ม | สถานการณ์ที่ใช้งาน | สิ่งที่ต้องการ |
|---|---|---|
| **คนหาอะไรทำสุดสัปดาห์** (กลุ่มหลัก) | ว่างเสาร์-อาทิตย์ อยากออกจากบ้าน | งานใกล้ตัว เรียงตามระยะทาง ดูเร็วว่าวันไหน กี่โมง ที่ไหน |
| **นักท่องเที่ยว/คนวางแผนทริป** | กำลังจะไปเที่ยวจังหวัดหนึ่ง | ดูงานตามจังหวัด + ช่วงวันที่ที่จะไป |
| **คนสายความสนใจเฉพาะ** | ตามงานดนตรี / คาร์มีท / workshop | กรองตามหมวดหมู่ในพื้นที่ที่เว็บครอบคลุม |
| **ผู้จัดงาน** | มีงานจะจัด อยากให้คนรู้ | ส่งข้อมูลงานเข้าระบบได้ง่าย ไม่ต้องเสียเงิน |
| **แอดมิน (ทีมเรา)** | ดูแลคุณภาพข้อมูล | กรอกงานเอง + อนุมัติ/ปฏิเสธงานที่คนส่งเข้ามา |

## 4. ขอบเขต MVP (Phase 1)

### ขอบเขตพื้นที่

เปิดรับงานเฉพาะ **ภาคตะวันออก** (7 จังหวัด: ชลบุรี ระยอง จันทบุรี ตราด ฉะเชิงเทรา ปราจีนบุรี
สระแก้ว) แทนทั่วประเทศ — เป็นการนำกลยุทธ์ "เจาะลึกก่อนกระจายกว้าง" ใน `05-marketing-plan.md`
มาใช้จริงโดยเลือกภาคที่ทีมมีความรู้พื้นที่เอง เพื่อกรอกข้อมูลได้แน่นและตรวจสอบได้จริงตั้งแต่
วันแรก แทนที่จะมีงานจังหวัดละ 1 งานกระจายบางทั่วประเทศ

ควบคุมด้วยค่าคงที่จุดเดียวที่ `src/lib/region-scope.ts` — ขยายไปภาคอื่นหรือกลับไปทั่วประเทศ
ทำได้โดยไม่ต้องรื้อโครงสร้าง เพราะข้อมูลอ้างอิงจังหวัดและแผนที่ยังเก็บครบทั้ง 77 จังหวัดเสมอ
(ดู `lib/data/provinces.ts`) มีแค่ชั้นกรองการแสดงผล/การเขียนข้อมูลเท่านั้นที่ถูกจำกัดไว้

### ต้องมี

- **หน้าค้นหา/เรียกดูงาน** พร้อมกรองด้วย จังหวัด, หมวดหมู่, ช่วงวันที่
- **"งานใกล้ฉัน"** — ขออนุญาตใช้ตำแหน่งจากเบราว์เซอร์ แล้วเรียงตามระยะทางจริง
- **หน้ารายละเอียดงาน** — ชื่อ, วันเวลา, สถานที่ + แผนที่, รายละเอียด, ลิงก์ไปหน้าผู้จัด
- **แอดมินหลังบ้าน** — เพิ่ม/แก้ไข/ลบงาน (ทีมกรอกข้อมูลตั้งต้นเอง)
- **ฟอร์มแจ้งงาน** — ส่งงานได้โดยไม่ต้องสมัครสมาชิก เข้าคิวรออนุมัติ ไม่ขึ้นเว็บทันที
  - *เลือกไม่บังคับล็อกอินเพราะ* การสมัครสมาชิกเป็นกำแพงที่ทำให้คนส่งงานน้อยลงมาก
    ซึ่งขัดกับเป้าหมายหลักช่วงแรกคือเก็บข้อมูลให้ได้เยอะที่สุด (ดูหัวข้อ cold start ด้านล่าง)
  - *แลกกับ* ความเสี่ยงเรื่องสแปม จึงต้องมีคิว moderation และบันทึกผ่านเซิร์ฟเวอร์
    ที่ตรวจข้อมูลก่อนเสมอ ไม่เปิดให้เขียนเข้าฐานข้อมูลตรงๆ (ดู `03-data-model.md`)
- **SEO พื้นฐาน** — SSR ทุกหน้า, structured data, sitemap, OG image (ดูเหตุผลใน `05-marketing-plan.md`)
- ใช้งานบนมือถือได้ดี และติดตั้งเป็น PWA ได้

### ยังไม่ทำใน MVP

ตัดออกเพื่อให้ปล่อยของได้เร็ว — ไม่ใช่ว่าไม่สำคัญ:

- ระบบสมาชิกสำหรับผู้ใช้ทั่วไป (ล็อกอิน, บุ๊กมาร์ก) → Phase 2
- ระบบแจ้งเตือนผ่าน LINE → Phase 2
- Dashboard ให้ผู้จัดงานจัดการงานตัวเอง → Phase 2
- การขายบัตร / ระบบชำระเงิน → Phase 3 (ถ้าทำ)
- แอป native → ประเมินหลังมี traction จริง

## 5. เกณฑ์วัดความสำเร็จ

เนื่องจากโมเดลช่วงแรกคือ **ฟรี เน้นผู้ใช้และทราฟฟิกก่อน** ตัวชี้วัดจึงไม่ใช่รายได้:

| ตัวชี้วัด | เป้าหมายช่วงแรก | ทำไมถึงวัดตัวนี้ |
|---|---|---|
| จำนวนงานที่ approved และยังไม่หมดอายุ | ≥ 100 งาน กระจายครบ 7 จังหวัดภาคตะวันออก | ถ้าข้อมูลบาง เว็บจะไม่มีประโยชน์ให้ใครกลับมา |
| ผู้ใช้ที่กด "งานใกล้ฉัน" | ≥ 30% ของผู้เข้าเว็บ | พิสูจน์ว่าฟีเจอร์แกนหลักตรงความต้องการจริง |
| งานที่คนส่งเข้ามาเอง / สัปดาห์ | ค่อยๆ เพิ่มขึ้น | ตัวชี้วัดว่า flywheel เริ่มทำงาน ทีมไม่ต้องกรอกเองทั้งหมด |
| Organic traffic จาก Google | เพิ่มขึ้นต่อเนื่อง | ช่องทางโตหลักที่ไม่ต้องใช้งบ |

## 6. ข้อสมมติและความเสี่ยง

**ความเสี่ยงที่ใหญ่ที่สุดคือ cold start ของข้อมูล** ไม่ใช่เรื่องเทคนิค — เว็บที่มีงานแค่ 10 งานจะไม่มีใครกลับมา และเมื่อไม่มีคนเข้า ก็ไม่มีผู้จัดงานอยากส่งงานเข้ามา

แนวทางรับมือ:
- ทีมกรอกข้อมูลตั้งต้นเองให้ถึงเกณฑ์ก่อนเปิดตัว (ดู `04-roadmap.md`)
- โฟกัสจังหวัด/หมวดหมู่ที่เรามีข้อมูลแน่นก่อน แทนที่จะบางทั่วประเทศ
- ทำ CTA "แจ้งงาน" ให้เด่นตั้งแต่วันแรก

ความเสี่ยงรอง: **ข้อมูลเก่า/ผิด** — งานเลื่อน ยกเลิก หรือข้อมูลเวลาไม่ตรง ทำลายความน่าเชื่อถือเร็วมาก จึงต้องมีสถานะงานและวันหมดอายุที่ชัดเจนตั้งแต่ data model
