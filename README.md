# Phikadfest

![Next.js 16](https://img.shields.io/badge/Next.js-16-black) ![TypeScript](https://img.shields.io/badge/TypeScript-5-blue) ![Tailwind CSS v4](https://img.shields.io/badge/Tailwind_CSS-v4-38bdf8)

เว็บไซต์รวมงานเทศกาลและกิจกรรมทั่วประเทศไทย — ค้นหาได้ว่ามีงานอะไรใกล้ตัว
หรือในจังหวัดที่กำลังจะไปเที่ยว

## ปัญหาที่แก้

ข้อมูลงานเทศกาลไทยกระจัดกระจายอยู่ตามเพจ Facebook ของผู้จัดแต่ละราย คนในพื้นที่จึงมักไม่รู้ว่ามีงาน
ใกล้ตัวจนงานผ่านไปแล้ว ส่วนนักท่องเที่ยวก็วางแผนทริปโดยไม่รู้ว่าช่วงนั้นมีงานอะไรในจังหวัดที่จะไป
Phikadfest รวมข้อมูลเหล่านี้ไว้ที่เดียว ให้ตอบได้ทันทีว่า "ตอนนี้มีงานอะไรน่าไปบ้าง"

## ฟีเจอร์เด่น

- 🔍 **ค้นหา/กรองงานแบบ real-time** โดยยังคง Server-Side Rendering และ SEO ไว้เต็มรูปแบบ (soft navigation ผ่าน `router.push`, ไม่ใช่ client-side filter ที่ต้องส่งข้อมูลทั้งหมดไปเบราว์เซอร์)
- 🗺️ **แผนที่ประเทศไทยแบบคลิกจังหวัดได้** พร้อมกล้องซูม/ลากที่คำนวณเอง — ไม่พึ่ง Leaflet หรือ Mapbox
- 📍 **หาตำแหน่งผู้ใช้อัตโนมัติ** แล้วซูมไปจังหวัดนั้น พร้อมช่องค้นหาจังหวัดด้วยข้อความสำหรับคนที่รู้อยู่แล้วว่าจะไปไหน
- 📝 **ระบบแจ้งงานเข้าคิวอนุมัติ** ป้องกันข้อมูลปลอม/ไม่น่าเชื่อถือขึ้นเว็บโดยไม่มีการตรวจสอบ
- 🌙 **ธีม Dark ทั้งเว็บ** ออกแบบให้เข้ากับบรรยากาศงานเทศกาลกลางคืน (โคมไฟ, ไฟประดับ)
- 🔎 **SEO/JSON-LD ต่อหน้างาน** ให้ Google แสดงผลค้นหาแบบพิเศษ (วันที่-สถานที่ในหน้าผลลัพธ์)

## Tech Stack

| ส่วน | เทคโนโลยี | ทำไมถึงเลือก |
|---|---|---|
| Framework | Next.js 16 (App Router) + TypeScript | SSR ในตัวสำคัญกับ SEO ซึ่งเป็นช่องทางโตหลักของเว็บนี้ ไม่ต้องแยก backend เป็นอีก service |
| UI | Tailwind CSS v4 | ปั้น UI ไว คุมธีม Dark ทั้งเว็บผ่าน CSS variable ชุดเดียว |
| ฐานข้อมูล | PostgreSQL + PostGIS (ผ่าน Supabase) | ฟีเจอร์ "งานใกล้ฉัน" ต้อง query ระยะทางจริงบนพื้นโลก ไม่ใช่แค่เทียบตัวเลขพิกัด |
| แผนที่ | Inline SVG + Web Mercator projection ที่เขียนเอง | ต้องการแค่รูปร่างจังหวัดที่กดได้และระบายสีได้ ไม่ใช่ภาพถ่ายดาวเทียม จึงไม่คุ้มเพิ่ม dependency |
| Hosting | Vercel + Supabase | Free tier ครอบคลุม MVP ทั้งคู่ เหมาะกับโปรเจกต์ที่ยังไม่มีรายได้ |

รายละเอียดและ trade-off ที่พิจารณาไว้ทั้งหมดอยู่ใน [docs/02-tech-stack.md](docs/02-tech-stack.md)

## จุดที่ตั้งใจออกแบบเป็นพิเศษ

- **แปลงข้อมูลขอบเขต 77 จังหวัดจาก GeoJSON เป็น SVG เอง** ด้วยสคริปต์ที่ทำ Web Mercator projection และหา "จุดที่อยู่ลึกที่สุดในเขตจังหวัด" (pole of inaccessibility — อัลกอริทึมเดียวกับที่ Mapbox ใช้) สำหรับวางชื่อจังหวัดให้อยู่ในเขตจริงเสมอ แม้จังหวัดรูปร่างเบี้ยวอย่างตากหรือประจวบคีรีขันธ์
- **กล้องแผนที่คำนวณเป็น "ความสูงที่มองเห็น" ไม่ใช่ค่า scale ตรงๆ** เพราะแผนที่ใช้ `preserveAspectRatio="slice"` ซึ่งทำให้ scale ค่าเดียวกันให้ผลต่างกันตามสัดส่วนจอ การคิดเป็นความสูงคงที่ทำให้กรอบภาพเท่ากันทุกอุปกรณ์
- **Schema ฐานข้อมูลออกแบบให้ PostGIS พร้อมใช้ตั้งแต่ต้น** พร้อม Row-Level Security คุมสิทธิ์การอนุมัติงานที่ระดับฐานข้อมูล ไม่ใช่แค่ตรวจในโค้ดฝั่งแอป
- **ข้อมูลตัวอย่างสำหรับพัฒนาแยกจากข้อมูลจริงอย่างชัดเจน** พร้อมแบนเนอร์เตือนอัตโนมัติ กันไม่ให้ข้อมูลปลอมหลุดขึ้น production โดยไม่ตั้งใจ

## โครงสร้างโปรเจกต์

```
docs/                     เอกสารโปรเจกต์ — อ่านก่อนเริ่มแก้โค้ด
supabase/migrations/      SQL schema และข้อมูลตั้งต้น 77 จังหวัด
scripts/                  สคริปต์แปลงข้อมูลแผนที่ (GeoJSON → SVG)
src/
  app/
    (site)/                หน้าเว็บทั่วไป (มี footer) — หน้าแรก, ค้นหางาน, แจ้งงาน
    map/                    หน้าแผนที่เต็มจอ (ไม่มี footer)
    api/                    HTTP endpoint — ฝั่ง backend
  components/
    map/                    ส่วนประกอบของหน้าแผนที่
  lib/
    events.ts               ชั้นเข้าถึงข้อมูล — จุดเดียวที่ต้องแก้ตอนย้ายไป Supabase
    map-camera.ts            คณิตศาสตร์ของกล้องแผนที่ (ฟังก์ชันบริสุทธิ์ ทดสอบได้)
    format.ts                จัดรูปแบบวันเวลา/ราคาแบบไทย (ตรึง timezone Asia/Bangkok)
    data/                    ข้อมูลอ้างอิงและข้อมูลตัวอย่าง
```
